# One coin, two gestures — and a flat coin icon

**2026-09-20.** A starting point for the design pass, not a finished look.
Everything here is built and running on a Pixel; every colour was measured off
an asset that already ships rather than picked by eye. All of it is meant to
be argued with.

## The idea in one line

**The app spins the coin; the arcade flips it.** Same coin, two axes.

Before this, the DGD app showed a photoreal three-quarter render and the
arcade showed a flat face-on coin — two different objects. Now both show the
same artwork, and the thing that tells the surfaces apart is how it moves.
Coming out of the ticker into the arcade, you should recognise the object and
notice you have arrived somewhere else.

|  | DGD app (ticker) | DGD Arcade |
|---|---|---|
| Gesture | **spin** — about the vertical axis | **flip** — end over end |
| Axis | `rotationY` | `rotateX` |
| Edge-on silhouette | a vertical sliver | a flat ellipse |
| Trigger | once when home appears, then on tap | on tap |
| Sound | the existing `open_coin` | `coin_flip` |

The arcade used to *alternate* spin and flip on each tap. That alternation is
what was given up to make the two surfaces distinguishable, and it is the
first thing to put back if the split does not earn its keep.

## Where it lives

| File | What |
|---|---|
| `android/.../animation/SpinningCoin.kt` | The spin. New file. Built and verified |
| `android/.../ui/TickerContent.kt` | Header calls `SpinningCoin` instead of a static `Image` |
| `android/.../res/drawable/dgd_coin_face.png` | The shared coin, copied from the arcade |
| `apple/.../Views/SpinningCoinView.swift` | The iOS spin. **Not compiled** — see below |
| `apple/.../Views/TickerView.swift` | One-line header swap |
| `puzzle-app/lib/main.dart` | Arcade hero coin: always flips |

The app's original `drawable/dgd_coin.png` is **untouched**. Reverting the
header to it is a one-line change.

**It is now unreferenced, and costs 547 KB in every install.** A grep of the
source (excluding `build/`) finds no use of it: the header takes
`dgd_coin_face`, and the launcher icon takes `ic_launcher_foreground`. It is
kept anyway, deliberately — it is DGD's own brand render and a designer
reverting to it should not have to go through git history. On a 77 MB app it
is 0.7%. Delete `drawable/dgd_coin.png` if you want the 547 KB back; nothing
will break. The same is true of `DGDCoin.imageset` on iOS.

### Three details that are load-bearing

**The coin does not idle-spin.** This is a price ticker. A permanently
rotating object in the header pulls the eye off the number the screen exists
to show, and keeps the GPU awake for nothing. It turns once on appearance —
alongside the open-coin sound that already played there — and then only when
tapped.

**There is a milled edge.** Without it the coin vanishes completely twice per
turn and reads as a dropped frame. It is a thin gold capsule behind the coin,
outside the rotating layer, faded in by `(1 - |cos θ|)³` so it only shows near
the turn instead of sitting on the face as a bright stripe.

**Past the quarter turn the artwork is flipped.** Otherwise you are looking at
the back of the image and "Digital Gold" reads mirrored. Flipping it makes
that the coin's *reverse* instead.

**Reduce-motion is respected.** The app already reads the platform's "remove
animations" setting; with it on the coin is static and taps do nothing.

## The icon

A flat gold coin. Not the photoreal render — flat, so it survives being 48dp
on a home screen.

It is **derived from the arcade's existing icon**, not drawn fresh:

- Gold sampled from that asset: `#FFD679` rim → `#FBCC61` body → `#F3BC42`
- Glyph colour `#5C3E04`
- The G itself is **lifted from the arcade icon as an alpha mask**, so the
  mark is provably the same one rather than a redraw that is subtly off
- Coin at **62% of the canvas**, which is the 72/108dp adaptive safe zone —
  any larger and a circular launcher mask crops the rim off

Generated by `arcade/integration/make_coin_icon.py`; rerun it to change
anything. Ships adaptive (foreground + background + **monochrome** for themed
icons), legacy density mipmaps, a round variant, and a 512px Play asset.

### The one thing I would flag

**The app icon and the arcade icon are now nearly identical.** Both are a flat
gold coin with the same G on the same near-black. I added a *milled double
rim* to the app's coin that the arcade's plain coin lacks, which is a real
coin-design convention and is visible at 48dp — but it is a thin distinction.

Whether that matters depends on a decision nobody has made yet: if the arcade
only ever ships **inside** the DGD app, there is one launcher icon and no
problem. If v1 also ships to the store standalone (`MERGE.md`, option C), two
near-identical icons would sit on the same home screen. That is a branding
call, not a technical one.

### Knobs

| Want | Change |
|---|---|
| Stronger/weaker perspective on the spin | `cameraDistance` in `SpinningCoin.kt` (currently Compose's default) |
| Faster/slower turn | `duration = 1100` in `SpinningCoin.kt`, `_toss` duration in `main.dart` |
| More/fewer turns on the flip | `* pi * 4` in `main.dart` — two full turns |
| Thicker coin edge | `fillMaxWidth(0.05f)` in `SpinningCoin.kt` |
| Different icon gold, glyph, rim, coin size | the constants at the top of `make_coin_icon.py` |
| Icon background | `res/values/ic_launcher_background.xml` — deliberately its own colour, so retinting the app's page does not move the icon |

## What is verified and what is not

**Verified on a Pixel** (screenshots in `shots/`):

- The spin runs, and a frame caught it edge-on with the milled edge showing
- The flip runs, edge-on on the opposite axis — visibly a different gesture
- Both surfaces show the same coin
- The launcher icon renders correctly through the system's adaptive mask
- The level sheet now clears the navigation bar
- **Reduce motion**: with `animator_duration_scale` forced to 0, the coin is
  static and three taps on it do nothing. No crash. (The setting was put back
  to 1 afterwards.)
- **Compact header**: the coin resizes 92 → 68dp when Stats expands and still
  renders correctly — a path that exists only because the header has two sizes

**Also green:** `flutter test` on v1 (34 passed, 6 skipped) and their Kotlin
unit tests. The Kotlin run finished in 4s, which looked like a cached result;
checking the task list showed `:app:testDebugUnitTest` with no `UP-TO-DATE`
marker, so it genuinely executed against the changed code.

The fix now has its own test — `test/sheet_margin_test.dart`, three cases,
mirrored into v2. It shipped without one, which is worth admitting: the device
check proves it once, the test proves it every run.

**Not verified on device: the end-of-run sheet.** Two sheets got the inset
fix; only the level sheet was driven on the phone, because reaching the other
means winning or losing a level and the embedded build has no DEV menu to
force it. It is the identical one-line change in an identically structured
widget, and the new test covers the shared arithmetic — but it has not been
seen with human eyes.

**Not verified: the whole iOS side.** `SpinningCoinView.swift` was written on
a Windows machine with no Xcode. It is the direct counterpart of the Kotlin,
and the one part that is easy to get wrong is handled deliberately — it
conforms to `Animatable` so the derived values (the edge sliver, the back-face
flip) track the turn instead of jumping to their final value, which is what a
plain `rotation3DEffect` under `withAnimation` would do. But it has never been
compiled. Review it, and if it is in the way, deleting that file and restoring
the one-line `Image("DGDCoin")` header reverts it cleanly.

The iOS icon (`AppIcon.appiconset/AppIcon.png`) was replaced; the previous one
is kept alongside this note as `AppIcon.previous.png`.
