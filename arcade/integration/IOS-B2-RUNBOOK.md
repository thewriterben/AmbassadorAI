# B2 — the iOS work, and how to run it on the Mac

**2026-09-21.** Everything here was written on a Windows machine with no
Xcode. **None of it has been compiled.** That is the single most important
sentence in this document: treat every Swift file below as a reviewed draft,
not as working code, and expect the first build to find something.

Two pieces, in order of how much they matter:

| | What | Risk if skipped |
|---|---|---|
| **B2a** | Delete the synthetic stats chart | The one genuine consumer-protection finding in Oleksandr's review is still shipping on iOS |
| **B2b** | Embed the arcade | iOS has no arcade at all; the app is half the product |

Do **B2a** first. It is small, it is the compliance item, and it does not
depend on Flutter being installed.

### Regenerate and build

The `.xcodeproj` is **XcodeGen output** and still lists the deleted files, so
it must be regenerated rather than edited:

```bash
cd apple
xcodegen generate          # brew install xcodegen, if needed
xcodebuild -project DigitalGoldTicker.xcodeproj \
           -scheme DigitalGoldTicker \
           -destination 'platform=iOS Simulator,name=iPhone 16' \
           clean build test 2>&1 | tail -40
```

## B2b — embed the arcade

### Why `.xcframework` and not CocoaPods

Flutter's published add-to-app instructions for iOS tell you to integrate via
CocoaPods. **Do not.** This project's `project.pbxproj` is generated by
XcodeGen from `project.yml`, and a Pods integration writes into the pbxproj —
so the next `xcodegen generate` silently discards it. Frameworks declared in
`project.yml` survive regeneration, which is the whole point.

This also matches the Android decision: the arcade ships as a built artefact
so the host app builds with no Flutter SDK present.

### Build the frameworks

Needs the Flutter SDK on the Mac. The arcade module is generated from v1 by
`arcade/integration/sync_module.py`, exactly as on Android — never edit the
generated module.

```bash
python3 arcade/integration/sync_module.py     # regenerates from v1, refuses if v1 is not on main
cd /path/to/dgd_arcade_module

flutter build ios-framework \
  --no-debug --no-profile \
  --dart-define=DGD_APP_TAB=true \
  --xcframework \
  --output=build/ios-frameworks
```

**`DGD_APP_TAB=true` is not optional.** Arcade plan §4.3 bars prize-style
celebration inside the DGD app, and that flag is what suppresses the arcade's
fireworks and spoken winner line. On Android it lives inside `build_aar.cmd`
precisely so it cannot be forgotten; iOS has no equivalent wrapper yet, so it
is on you. Consider adding one.

Output: `Flutter.xcframework`, `App.xcframework`, and one per plugin
(`audioplayers_darwin`, `shared_preferences_foundation`, `url_launcher_ios`,
`jni`). Copy the `Release/` set into `apple/Frameworks/`.

### Declare them in `project.yml`

```yaml
targets:
  DigitalGoldTicker:
    dependencies:
      - framework: Frameworks/Flutter.xcframework
        embed: true
      - framework: Frameworks/App.xcframework
        embed: true
      - framework: Frameworks/audioplayers_darwin.xcframework
        embed: true
      - framework: Frameworks/shared_preferences_foundation.xcframework
        embed: true
      - framework: Frameworks/url_launcher_ios.xcframework
        embed: true
      - framework: Frameworks/jni.xcframework
        embed: true
```

Then `xcodegen generate`.

### The entry point

The Android side is `arcade/Arcade.kt`: a cached warm engine started after the
ticker's first frame, and an `open()` that presents it. The iOS counterpart is
`FlutterEngine` + `FlutterViewController`, presented from the existing
`TickerScreen`. Warm it in a `.task` on first appearance — **not** at app
launch, or Dart startup competes with the stats fetch, which is the reason the
Android version is where it is.

Mirror the Android placement: a text button top-left of the ticker home,
opposite "Log in", reading "Arcade". `TickerView.swift`'s `header` is where
the equivalent lives.

I have deliberately **not** written this file. The Android version took three
attempts to get the engine lifecycle right, and guessing at Swift I cannot
compile would produce something that looks finished and is not. The shape
above plus `android/.../arcade/Arcade.kt` as the reference is a better
starting point than a plausible-looking file.

### Expect

- **App size.** Android went from 18.8 MB to ~77 MB with the arcade embedded.
  iOS will grow comparably. Thin with App Thinning; check the size report.
- **Bitcode.** Long gone, but old Flutter docs still mention it. Ignore.
- **Simulator slices.** `--xcframework` includes them; device-only builds do
  not need them but they are harmless.

## Also in the tree, also uncompiled

`DigitalGoldTicker/Views/SpinningCoinView.swift` (from the coin work) and its
one-line use in `TickerView.swift`'s `header`. Same warning applies. If it is
in the way, delete the file and restore `Image("DGDCoin")`; details in
`COIN-AND-ICON.md`.

The part most likely to be wrong is the `Animatable` conformance in
`CoinSpin` — it is what makes the derived edge-sliver and back-face values
track the animation instead of jumping. If the coin spins but the edge flickers
or the artwork flips instantly, that conformance is where to look.
